+ 发送与接收
	- tcp 异步发送，
		* 指将数据交给操作系统，但是并不知道操作系统有没有发送出去，
		* 等待原因，可能是发送缓冲区满了。
		* 可以自己设置超时取消，异步发送tcp不支持直接设置超时，SendTimeout参数在异步发送这里没有用。
		* 立马报错结束任务，原因可能是网卡坏了之类的

	- tcp 异步接收，
		* 指从操作系统接收缓冲区读取数据
		* 等待原因，服务器一直没有发送数据，或者没有发送成功数据
		* 可以自己设置超时取消，异步接收tcp不支持直接设置超时，ReceiveTimeout参数在异步接收这里没有用。
		* 立马报错结束任务，原因可能是 socket关闭了，有报错，或者能读到至少一个字节，或者连接关闭了
		* 这一层默认应该是没有超时设置的，超时设置应该在心跳层

+ 数据加密
	- 功能
		* 加密防止窃听
		* 加密校验防止篡改
		* 完整性校验
		* 双方真实身份校验
	- 非对称加密
		* 数学本质
			+ 不好搞，不明白
			+ RSA， 三个人名手写字母组成
		* 钥匙
			+ n=pxq,n大小一般是2048bit左右大小的数,也就是n必须是2048bit的。
			+ 公钥，(n, e) 大小比2048bit大些，一般256B
			+ 私钥，(n, d) 还存了很多其他的数，大小比公钥大的多一般，1.5KB
			+ 加密内容：
				- 大小可以很大，但是一次加密必须是256字节，也就是n的长度。
				- PKCS协议就是小数据如何扩充到标准256字节
		* 使用方式
			+ 非对称加密，一般不会加密大量数据，一般就是加密小于256B的数据。要传送大数据，就要对大数据AES加密，然后将AES密码使用非对称加密发送过去。
			+ 公钥只能加密，需要加密函数。私钥只能解密，需要解密函数。
			+ 私钥可以签名，需要签名函数，公钥可以验证签名，需要验证签名函数。
			+ 记住私密消息，只能用公钥加密，私钥解密，不能用私钥签名，公钥验证签名，做私密消息通信。后者不成喇叭了吗？
		* 加密
			+ 目的建立私密通道，我要让你给我发私密信息，就给你一个公钥。建立了你到我的通道。
			+ 建立双向私密通道，就需要你也给我个公钥。
		* 签名
			+ 目的身份验证
				- 双方都有对象的公钥，但是其他人也有对方的公钥，如果有人其他发信息也就会是误以为是对象发信息
				- 如果对象发的信息里附带它的私钥签名，则我用它的公钥验证，就知道他是他了

				- 证书扩展名：der,pem明确指明证书格式。cer,crt不指明证书格式，证书可能是der,也可能是pem

					* 申请者公钥，加密算法
				- 签名算法和结果：这部分根本就不能放在待签内容中，因为签名结果会改变签名内容啊，循环了没法签啊
					* 对签名内容使用的，摘要算法和签名算法。
					* 签名结果：要验证的话就，对签名内容摘要，然后解密签名结果。对比摘要和签名结果是否相同。但是签名结果，浏览器里可能不会显示出来。
				- 证书指纹：整张证书的摘要指纹，它不包含在证书里面。包含在里面证书就没法摘要了。但是它会显示到浏览信息里，这是操作系统做的事情

		* 证书的内容大致作用
			- 他是谁，你可以叫他什么。他可能有很多名字。比如域名或者ip通配符匹配
			- 他的公钥。 你可以使用这个验证他的身份。
			- 机构身份。凭什么这个公钥就是这个身份呢？
			- 中间机构签名。表明机构对上面内容负责。不信你验证我的签名是不是对上面的内容负责的签名。
			- 中间机构证书。中间机构你是谁啊。哦原来你有官方机构发的证书。
		* 证书链
			+ 根证书机构，之所以受信任，是因为根证书机构信息已经装在了操作系统里了
			+ 中间CA, 它需要根证书给它颁发证书。
			+ 所有通过中间CA发的证书，必须有CA从根证书申请的证书。
			+ 本机根证书，中间CA证书，服务器证书
		* 证书保存
			+ baidu.com-public-only.pfx， 实际上就是证书集合。 他可以保存带私钥的集合，所以他有了保存私钥的功能
			+ X509Certificate2Collection X509Certificate2 可以创建 pfx,记得使用2,2代表功能更全，支持的更多。比如X509Certificate不能添加私钥。
		* 怎么创建证书
			+ 使用c#创建
		* 标准流程
			+ 创建CA
				- 创建不带私钥的根CA证书,和带私钥的根CA证书
				- 带私钥的根CA证书,离线保存，给服务器颁发证书
				- 不带私钥的根CA证书,让客户端下载到本地，让本地使用根CA证书去验证服务器证书
			+ 客户端连接服务器，发送1、TLS版本等信息 2、本次验证证书公钥
			+ 服务器发送1、本次验证证书公钥，并下发证书集合
			+ 客户端使用根证书校验证书正确
			+ 客户端随机生成AES密钥，并发送给服务器，表示本次连接通话，使用这个AES密钥通话


+ 帧协议
	- 分帧任务
		* 主要靠消息头大小，消息体大小，区分帧间隔
		* Magic,可以判定帧的开头，但是主要是作为协议的名字
	- 版本兼容
		* Version, 一个版本号决定了，消息头的解析和消息体的解析
	- 服务器路由
		* MessageType，可以决定服务器路由
	- 消息对称
		* RequestId long持续增长,客户端可以知道服务器回复的是哪条消息
	- 消息分片
		* FragmentInfo，当消息超过协议的最大帧数据载荷，消息需要分片
	- 附带数据往返时间
		* Timestamp

			/// 消息头解析失败，接收方需要主动关闭连接，重新连接
			public struct TCPNetProto
			{
			    
			     1、承担部分分帧任务
			     2、主要承担分帧任务是消息头协议，消息体长度，消息体，这种固定格式分帧
			     3、magic可以额外作为分帧的一个检查项，因为tcp已经完全胜任分帧任务了，这个可以检查万一发送的协议不对，相当于一协议的名字
			     4、包：没有明确概念，应用层一般指一帧的数据。
			    
			    public int Magic;
			    // 整个协议的版本，包含消息头的解析协议和消息体的解析协议
			    public byte Version;
			    
			     1、标记消息类型，给网关路由信息
			     2、消息类型，同时也给出了数据的解析结构信息
			    
			    public ushort MessageType;
			    // 本次请求的id, 从0递增，主要用来判断，服务器是否回复了本次请求
			    public ulong RequestId;
			    // 发送方发送时的时间，服务器接收后，复制该值，返给客户端，客户端算出往返时间。这个时间客户端可以自己定义，Unity的Time.time即可。
			    public uint Timestamp;
			    // 用于消息分片,当消息超过协议帧最大数据量
			    public FragmentInfo FragmentInfo;
			    public uint PayloadLength;
			    public ushort HeaderLength;
