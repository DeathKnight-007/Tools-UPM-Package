## 2. 页面方案与复用结论

### 2.1 页面级映射

| 页面 | 复用方式 | 结论 |
|---|---:|---|
| `QXFKJPanel` 活动外壳 | 方式 5：专项页面 | 复用 BasePage 生命周期、公共活动数据和通用子页；布局、页签组织由本活动实现。 |
| `QXFKJSubPanel` 祈愿页 | 方式 5：专项页面 | Spine、大奖、气泡、抽奖按钮和进度条均为活动定制。 |
| 奖池选择 | 方式 1：直接复用 | 直接打开 `ItemChoosePanel`，不新建选择弹窗。 |
| 规则 | 方式 1：直接复用 | `RulePopPanel`，正文读取 `db_activelist[activityid].faq`。 |
| 排行榜 | 方式 1/2 | 复用现有公共活动排行页及 `CommonActiveMgr.RequestRankInfo`；具体 PageName 由同批活动入口配置核定。 |
| 抽奖任务/进度 | 方式 2：组合复用 | 复用 `CommonDrawTask` 原子组件，活动页负责传入任务和积分数据。 |
| 商店、每日礼包、战令、任务 | 方式 2：组合复用 | 使用预制体内已有 `ActivityCommonShopPanel`、`CommonShowDailyGift`、`ActiveBattlePassSubPanel`、`ActivityCommonTaskPanel`。 |

### 2.2 职责边界

- `CommonActiveData`：解析可跨活动复用的 `activerecruitpatern` 与 `newrecruit` 数据结构。
- `CommonActiveMgr`：保存服务器活动数据、提供查询、发起公共协议、广播公共数据变化。
- `QXFKJMgr`：维护当前奖池、组装本活动 ViewData、发起祈愿/切换大奖、计算按钮状态和红点。
- `QXFKJPanel`：活动壳、页签与通用子页生命周期。
- `QXFKJSubPanel`：只做绑定、事件转发、视图刷新和 Spine 资源生命周期。
- 不把 `item1～item6` 的顺时针布局等活动专属规则下沉到 `CommonActiveMgr`。

在 `CommonActiveData:Init()` 中调用 `InitActiveRecruitPattern()`，按活动 ID 缓存到 `self.activeRecruitPattern`；分隔字符串统一转为 number，界面不直接 Split 配置字符串。

| 5 | 1323 | 石田三成，语言 ID `651323` | `Effect_hero_show_URstsc_1323_spine` | `1;1;340230` | `10;10;340230` |
| 6 | 1324 | 浅野长政，语言 ID `651324` | `Effect_hero_show_qycz_1324`（字段为 `animation`） | `1;1;340230` | `10;10;340230` |

实现必须兼容 `db_hero.animation1` 与 `db_hero.animation` 两种字段，优先 `animation1`。主界面英雄 Spine、中央最终大奖和 `ItemChoosePanel` 中的奖池代表物，三者均以当前池的 `rewardtier` 为唯一数据源。

### 3.3 配置校验

- `newrecruitid` 为空、池不存在或 `rewardtier` 无效：屏蔽祈愿按钮并上报错误日志。
- `lastrecruitid` 不在当前 `newrecruitid`：回退第一个池，仅用于展示；首次确定仍以服务器规则为准。
- `single/multi` 解析为 `{drawCount, costCount, itemid}`，发送次数使用 1/10，消耗显示使用配置值。
- `itemShow` 数量应与气泡槽数量严格相等；不允许静默截断。

## 4. 服务器协议分析

### 4.1 协议编号及公共发送

- C2S：`MessagesProto.C2S_DceActivityOpt = 1113`
- S2C：`MessagesProto.S2C_DseActivityOpt = 2156`
- 继续复用 `Controller/Net/ActivityAction.lua`，不新增 Action。
- `ActivityAction.Send` 默认 `waitFlag=true`，按钮点击后依赖网络层等待遮罩防止连点；收到响应或错误响应后由现有网络框架解除。

### 4.2 祈愿

```lua
ActivityAction.Send({
    type = 90,
    activityid = activityid,
    contentid = currentPoolId,
    actval = drawCount, -- 1 或 10
})
```

按需求，`type=90`、`actval=1/10`。`contentid` 传当前 `newrecruit.id`，用于明确奖池；若服务端最终规定奖池只认 `lastrecruitid`，该字段保持兼容且不影响客户端逻辑。

S2C `type=90` 处理：

1. `ValidateReceive("DseActivityOpt", msg)` 失败立即返回，页面不预扣资源、不本地加积分。
2. `GameEventsMgr.changeData(msg.acitivtylst)` 更新 `ExActivityInfo`。
3. `QXFKJMgr.UpdateFromServer_Draw(msg.recruitresult, msg.reward)` 保存结果并广播 `QXFKJMgr.Noticonst.DrawResult`。
4. 同时广播 `CommonActiveMgr.Noticonst.DrawGotReward`，让通用抽奖任务/积分链刷新。
5. 结果表现优先使用 `msg.reward.items`；若本活动沿用招募结果面板，则由 `QXFKJSubPanel:OnDrawResult` 组装并打开现有招募结果页，不能在 Action 内写活动 UI。

### 4.3 切换大奖

```lua
ActivityAction.Send({
    type = 91,
    activityid = activityid,
    contentid = currentPoolId,
    actval = 1,
    poolId = targetPoolId,
})
```

`ActivityAction.Send` 增加 `type=91` 分支：

```lua
msg.selectrecruitreq.optype = 1
msg.selectrecruitreq.id = args.poolId
msg.selectrecruitreq.singlerecruit = 1
```

S2C `type=91`：先 `GameEventsMgr.changeData(msg.acitivtylst)`，再由 `QXFKJMgr.UpdateFromServer_SelectPool(msg.selectrecruitresult)` 读取最新 `lastrecruitid` 并广播 `PoolChanged`。界面只有收到成功响应后才切换 Spine、大奖和消耗，失败保持原池。

### 4.4 服务端活动数据

`ExActivityInfo` 使用：

- `activityid`：活动实例 ID。
- `endtime`：主界面倒计时。
- `scoreinfo.score` / `scoreinfo.scoreinfolst`：积分和阶段奖励状态。
- `valcnt1`、`valcnt2`：现阶段协议注释仅为通用计数，未经后端定义不得硬编码业务含义。
- `lastrecruitid`：当前选中 `newrecruit.id`。

### 6.4 页面生命周期

`QXFKJPanel:OnEnter`：锚点归零 → `Init()` → `QXFKJMgr.Init(activityid)` → 初始化主祈愿页及通用子页 → 注册公共活动/背包/零点事件 → 激活默认页签。

`QXFKJSubPanel:OnEnter`：绑定 DrawResult、PoolChanged、TaskChange、PackageOrGoldSliverChange → 创建六个气泡卡片 → `RefreshAll()` → 启动每秒倒计时。

`OnHide/OnShow`：页面被弹窗遮挡不销毁 Spine；Show 时轻量刷新背包数量和倒计时。

`OnExit`：移除全部 Event 监听、Timer、按钮临时回调，回收卡片和 Spine；通用子页逐个 `OnExit()`。所有闭包保存在成员变量，保证 RemoveListener 使用同一引用。

### 6.5 页签与公共子页

主祈愿、任务、商店、战令、每日礼包按实际活动开放配置组装 `toggleitems`。每个元素包含 `subpage/onActive/onDeactive/redCheck/endtime`，沿用项目 UI Template 的 Toggle 组织方式。未开放子页不创建、不显示页签；活动专属背景仍由 `QXFKJPanel` 统一承载。

### 6.6 红点

- 祈愿红点：活动未结束、当前池有效且背包拥有至少一次 `single` 消耗。
- 任务红点：复用 `CommonDrawTask` / CommonActive 任务可领取判断。
- 商店、战令、礼包红点：调用对应公共子页 `Red()`，不在 QXFKJ 重写规则。
- 刷新时机：初始化、背包变化、任务变化、type 90/91 回包、零点、页签切换。
- 统一广播 `QXFKJMgr.Noticonst.RedChanged` 给页面入口；计算函数必须无副作用。

## 7. 完整交互链路

### 7.1 单抽/十抽

`choose_btn1/10` → `QXFKJSubPanel:OnDrawClick(count)` → `QXFKJMgr.CanDraw` → `QXFKJMgr.RequestDraw` → `ActivityAction.Send(type=90, actval=1/10)` → S2C 2156 → `ActivityAction.Execute` → `GameEventsMgr.changeData` → `QXFKJMgr.UpdateFromServer_Draw` → 奖励表现 + 主界面/任务/红点刷新。

### 7.2 切换奖池

`rewardpool_btn` → `ItemChoosePanel` → 用户选择以 `rewardtier` 表示的奖池 → 确定回调 index → `QXFKJMgr.RequestSelectPool` → `ActivityAction.Send(type=91)` → 成功回包 → `lastrecruitid` 更新 → `PoolChanged` → Spine、英雄名、中央大奖、抽奖消耗同步刷新。

## 8. 异常与边界处理

- 活动结束：停止倒计时，禁用祈愿和切池，保留只读展示；按产品统一逻辑关闭页面。
- 资源不足：走项目统一道具不足/跳转获取提示，不发协议。
- 连点：网络 `waitFlag=true` + 按钮交互态双保险，不本地模拟成功。
- Spine 加载竞态：保存 load token/poolId；异步返回时若池已变化则立即回收旧结果。
- 回包无 `acitivtylst`：不得访问 `[1]`；记录协议异常并仅处理明确存在的奖励字段。
- 切池失败：保持原奖池和原 Spine。
- 配置热更导致池删除：重新按服务器 `lastrecruitid` 对齐，失配则降级首池并禁用协议操作直至数据一致。
